# 웹 에디터 수정 기록 — 2026-11-09

## 원본 0.7.0 재검토

0.6.0 기반 수정 후 [원본의 최신 main 커밋 `1a96e2e`](https://github.com/dotoritos-kim/bms-electron-app/commit/1a96e2e3107ad29a2449d74023813b469e652ec5)를 다시 확인하고 웹 빌드의 기준으로 고정했다. 이 커밋은 0.7.0 및 문서 후속 변경을 포함한다. 기존 수정 이력을 되돌리는 대신 새 원본 위에서 보정 필요 여부를 다시 검토했다.

| 항목 | 최신 원본 확인 결과 | 웹 빌드 처리 |
| --- | --- | --- |
| 자동 생성·패턴 배치의 BGM 키음 이어받기 | 0.7.0에 추가됨 | 원본 구현 사용 |
| 변박 마디의 그리드 표시 | 마디 길이에 분할 수를 압축하는 기존 코드 유지 | 표시·스냅 일치 보정 유지 |
| 여러 노트의 BGM↔키 레인 드래그 | 잡은 노트의 ID를 전달하지 않음 | 기준점 보정 유지 |
| 다운로드 BGM 열 | 동시 발음 기준으로 줄을 재분할함 | 빈 열과 열 순서 보존 유지 |
| BGM 배치 옵션 | 설정 저장은 있으나 현재 차트 즉시 적용 없음 | 즉시 적용 보정 유지 |
| 화면·곡 위치 동기화와 휠 | 고정 4박 이동 및 별도 탐색 경로 유지 | 탐색 보정 유지 |
| 기본 탭 LNMODE | 필드 없음 | 기존 custom 헤더 경로로 지원 유지 |

원본과 세 서브모듈을 모두 해당 커밋으로 고정했다. 세 라이브러리의 커밋은 바뀌었지만 `src/` 파일 내용은 이전 고정 버전과 같았다. 웹 보정 12개 대상 파일의 교체 지점·개수를 모두 대조했고, 중복 적용할 수정은 없었다. 원본의 새 `autoKeysound` 및 전체 `editorStore` 단위 검사를 웹 회귀 검사에 포함해 BGM 키음 소비, 중복 방지, 실행 취소와 기존 보정의 공존을 확인한다.

최신 기준 검증: 프로덕션 빌드 성공, 11개 테스트 파일에서 **319개 통과·1개 건너뜀**, 새로운 TypeScript 진단 없음. 선택 검사 중 사용자 제공 원본의 읽기·저장 재파싱은 실행했고, 이전 브라우저 다운로드 파일을 요구하는 검사 1개는 건너뛰었다. 최신 프로덕션 번들의 브라우저 홈 진입·새 차트 생성·편집기 로딩과 기본 탭 LNMODE 표시를 확인했다. 아래의 상세 브라우저 드래그·다운로드 조작 기록은 최초 0.6.0 기반 보정 당시 결과다.

## 동작과 원인

- **그리드:** `1/4`는 차트 BPM에 상관없이 0.25박이다. BPM 188이면 약 79.787ms, BPM 120이면 125ms이며 120이나 188을 전역 작업 기준으로 강제하지 않는다. `#xxx02:0.75`인 3박자 마디에는 12칸, `1/3`에는 9칸을 그린다. 기존 표시는 분할 수를 마디 길이에 맞춰 압축해 실제 스냅보다 4/3배 촘촘했다. 이제 표시와 스냅이 같은 tick 간격을 사용한다. 원본 BPM·노트 타이밍은 변경하지 않는다.
- **여러 BGM 노트 이동:** BGM에서 키 레인으로 드래그할 때 실제로 잡은 노트를 목적지 기준으로 삼는다. 이전에는 항상 가장 왼쪽 노트를 목적지에 놓았다. 반대 방향도 잡은 노트를 기준으로 상대 간격을 유지하며, 경계에서는 묶음 전체를 제한한다.
- **BGM 저장:** 화면의 열 번호를 각 마디의 `#xxx01:` 줄 순서로 내보낸다. 앞쪽 빈 열은 `00` 줄로 유지한다. 같은 열·위치의 충돌은 추가 줄에 보존해 키음이 사라지지 않게 한다. 기존 저장기는 동시 발음만 기준으로 줄을 다시 묶어 악기별 열을 잃었다.
- **편집 옵션:** BGM 배치 변경을 현재 차트에 즉시 적용하고 브라우저 설정에 저장한다. 파일의 BGM 열을 유지해서 다시 열려면 **원본 순서**를 선택한다. 최근 파일·파일 연결·자동 저장은 페이지 수명에 한정되지만 편집 옵션은 로컬 저장소를 사용한다. 저장소가 차단되거나 사이트 주소가 달라지면 설정을 공유하지 못한다.
- **탐색:** 정지·일시정지 상태의 화면 스크롤을 위쪽 곡 위치에 반영한다. 위쪽 탐색과 미니맵은 재생 중에도 같은 seek 경로를 사용한다. 휠은 고정 4박 점프 대신 실제 이동량을 반영한다.
- **LNMODE:** 차트 정보의 **기본 → LNMODE**에서 미지정·1(LN)·2(CN)·3(HCN)을 선택한다. 기존 custom 헤더 저장 경로를 사용하므로 Raw·커스텀 탭과 저장 결과가 일치한다. 이는 헤더 편집 지원이며 웹 플레이어의 CN/HCN 판정 구현을 추가한 것은 아니다. 값의 의미는 [beatoraja 공식 확장 정의](https://github.com/exch-bms2/beatoraja/blob/master/manual/extension.txt)를 따른다.

## 구현 위치

`bms-studio/editor-patches.mjs`를 Vite의 사전 변환에 연결했다. 고정된 외부 소스 체크아웃을 수정하지 않고 웹 빌드에만 적용한다. 각 교체 지점과 개수를 검증하므로 상위 소스가 바뀌면 조용히 누락되는 대신 빌드가 실패한다. 일반 다운로드·키음 연결은 기존 브라우저 어댑터를 그대로 사용한다.

## 검증 명령

저장소 루트에서 기존 잠금 파일의 의존성을 준비한 후 실행한다.

```sh
node bms-studio/build.mjs
node bms-studio/check.mjs
node bms-studio/.source/node_modules/vitest/vitest.mjs run --config bms-studio/vitest.config.mjs
```

`BMS_REPRO_FILE` 환경 변수에 사용자 제공 BMS의 절대 경로를 지정하면 원본을 읽기만 하여 그리드 및 저장·재파싱을 검증한다. 선택적으로 `BMS_EXPORTED_FILE`을 지정하면 브라우저에서 실제 다운로드한 파일도 원본의 모든 오브젝트 위치·열·키음과 비교하고, 테스트에서 선택한 `LNMODE=3`을 확인한다. 개인 차트는 저장소나 테스트 픽스처에 복사하지 않는다.

`check.mjs`는 패치 전후 TypeScript 진단을 비교한다. 고정 소스에는 기존 진단 4개(반환 경로 2개, worker 타입 2개)가 있으며 이번 수정으로 추가되는 진단은 없어야 한다. 전체 TypeScript 검사가 무경고라는 뜻은 아니다. 상위 `writer.test.ts`의 10개 검사는 작성자의 외부 음악 라이브러리가 없어 실패했으며, 재현 가능한 기본 검증에는 합성 데이터를 사용하는 writer 검사와 사용자 제공 차트 검사를 사용한다.

## 브라우저 확인

1. 제보 차트를 열고 `1/4`를 선택해 3박자 마디에 12칸인지 확인한다. `1/3`은 9칸이다.
2. BGM 원본 순서를 적용하고 저장한 파일을 다시 열어 열을 대조한다.
3. BGM 여러 개를 선택하고 가운데·오른쪽 노트를 잡아 키 레인으로 이동한다. 기준 노트와 간격을 확인하고 실행 취소한다.
4. 미니맵, 위쪽 곡 위치, 휠을 움직여 화면과 곡 위치를 확인한다.
5. 기본 탭의 LNMODE를 변경·제거하고 다운로드한 헤더를 확인한다.

로컬 수정이며 운영 사이트 배포는 별도다. 실제 키음 파일이 제공되지 않아 음원 청취와 CN/HCN 플레이 판정은 이 검증에 포함하지 않는다.

제보 차트의 실제 브라우저 다운로드에서 모든 오브젝트의 위치·채널·키음·BGM 열, BPM과 마디 길이의 보존을 확인했다. BGM 7,257개와 롱노트 4개를 포함한 저장·재파싱 검사도 통과했다. 합성 차트의 오른쪽 BGM 노트를 잡아 5번 키 레인으로 이동하면 묶음이 3·4·5번에 놓이고 실행 취소로 복원되는 것을 브라우저에서 확인했다. 새로고침 후 원본 순서 옵션 유지, 미니맵·휠과 곡 위치의 동기화, LNMODE 선택·다운로드도 확인했다.
